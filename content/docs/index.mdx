CodeTurtle is a **repository-aware AI code reviewer** for GitHub pull requests. It reviews every PR against your full codebase — diff intent, dependencies, conventions, and prior patterns — and posts a structured, actionable review directly on the PR: inline findings, suggested fixes, and a 0-10 score.

## Quick start

<Steps>
  <Step>
    **Sign in with GitHub.** CodeTurtle requests read access plus `admin:repo_hook` so it can register a webhook on each repository you connect.
  </Step>
  <Step>
    **Connect a repository** from the [Repositories](/repositories) page. CodeTurtle creates a signed webhook on that repo automatically.
  </Step>
  <Step>
    **Open a pull request.** The webhook fires, the pipeline runs, and a review lands on the PR - usually in under a minute.
  </Step>
</Steps>

Or jump straight to [Getting started](/docs/getting-started) for the full walkthrough.

## Why repository-aware reviews?

Generic AI review tools comment on the diff in isolation. CodeTurtle grounds every finding in your actual codebase:

- **Conventions are enforced, not guessed** - naming patterns, error handling, and architecture choices from your repo are part of the review context.
- **Fewer false positives** - findings that conflict with your codebase's established patterns are filtered by a dedicated judge pass.
- **Suggestions you can act on** - every issue references the file and line, with a concrete fix.

## What a review contains

Each posted review includes:

| Section | What it is |
| --- | --- |
| **Overall score** | 0-10 quality signal for the change as reviewed |
| **Issues** | Bugs, security concerns, and logic errors with file/line references |
| **Suggestions** | Non-blocking improvements and refactoring ideas |
| **Positives** | What the PR gets right - so good work gets reinforced |

Reviews on PRs with critical issues request changes; everything else posts as a standard comment.
